# 想定される失敗パターン

実装前に書き出した「壊れ方」の一覧。E2E（リプレイ）フィクスチャはこの一覧を元に作っている。
`[E2E]` が付いたものは `e2e/fixtures/` にケースがある。

## 対象機能

| トリガー | 動作 |
|---|---|
| 3本指でクリック | 中クリック（カーソル位置） |
| 4本指でクリック | ⇧⌘5 |
| TipTap左（2本指を置いたまま、その左側を1本指でタップ） | 中クリック（カーソル位置） |

## クリック系（3本指 / 4本指）

1. `[E2E]` 1本指・2本指の普通のクリックを誤って変換してしまう（通常操作が壊れる。最悪の失敗）
2. `[E2E]` 3本指クリックが中クリックにならない
3. `[E2E]` 4本指クリックで ⇧⌘5 が出ない、または左クリックも同時に通ってしまう
4. `[E2E]` 押下中に指の本数が変わる（3本で押して2本で離す等）→ down と up の種類が食い違い、ボタンが押しっぱなしになる。down 時の判定を up まで保持する必要がある
5. `[E2E]` 3本指で押したままドラッグ → leftMouseDragged が素通りして、中ボタン押下中に左ドラッグが混ざる
6. `[E2E]` 5本以上の指 → 何もしない（素通り）べきところで誤発火
7. `[E2E]` 触れていない指（ホバー・離れかけの状態）まで本数に数えてしまう
8. ⇧⌘5 送信時に修飾キーが残って、その後の入力に Shift/Cmd が付く
9. `[E2E]` ハプティックや ⇧⌘5 が押した瞬間に出てしまう（BTT は押したときは通常のクリック感だけで、離したときに設定したハプティックと動作が出る）
26. `[E2E]` タッチデータが古い（デバイスのコールバックが止まっている）まま判定してしまう → 4本触れた最後のフレームのあとの通常クリックが ⇧⌘5 になる（PR #1 のレビューで指摘）。0.25 秒より古いフレームは使わない
27. `[E2E]` 左クリックの入力元を見ずに判定してしまう → 片方のトラックパッドに4本置いたまま、別のトラックパッドを1本指でクリックすると ⇧⌘5 になる（PR #1 のレビューで指摘）。Force Touch のトラックパッドは押す力でクリック元を特定する（43〜）。押す力が分からないトラックパッドでは、新しい接触がそのトラックパッド1台だけのときだけ判定し、それ以外はそのまま通す
28. `[E2E]` トラックパッドに3本以上置いたまま、マウスでクリックすると変換されてしまう → Force Touch のトラックパッドでは、押す力が弱ければ（指を置いただけなら）クリック元とみなさない。押す力が分からないトラックパッド（Magic Trackpad 1 など）では既知の制限として残る


### クリック元の特定（Force Touch、#2）

CGEvent の左クリックには、どのトラックパッドで押されたかの情報が無い。BTT 6.723 もクリックの判定はフレームの押す力（指の最大値）だけで行っていて、CGEvent とは突き合わせていない。
ここでは、フレームの押す力とクリックの時刻を突き合わせて、クリック元のトラックパッドを決める。

43. `[E2E]` 指を置いただけ（押す力 0〜35 程度）のトラックパッドをクリック元とみなす → マウスのクリックが中クリック / ⇧⌘5 になる。押す力が 50 以上になったトラックパッドだけをクリック元にする
44. `[E2E]` 2台のトラックパッドに同時に触れていると、3本指／4本指クリックが効かない（#24 の対処の副作用）→ 押す力で1台に決まるなら、もう1台に触れていても判定する
45. `[E2E]` 片方に3本以上置いたまま、もう片方を1本指で強く押してクリックすると、置いているだけの方の本数で判定する → 押した方の本数で判定する
46. `[E2E]` 押す力の強いフレームが左クリックのイベントより遅れて届き、クリック元が分からずにそのまま通してしまう → 3本以上触れている Force Touch のトラックパッドがあるときだけ、押す力が届くのを最大 30ms 待つ
47. `[E2E]` 待ちすぎる → 30ms を過ぎても押す力が届かなければ、マウスのクリックとみなしてそのまま通す
48. `[E2E]` 3本以上触れているトラックパッドが無いのに待ってしまい、通常のクリック（マウス・1本指）が遅れる → 待たない
49. `[E2E]` 少し前に強く押した記録が残っていて、あとのマウスのクリックをトラックパッドのクリックと誤認する → 押す力が 50 以上だった最後のフレームが 80ms 以内のときだけクリック元とみなす
50. `[E2E]` 強く押した直後にコールバックが止まり、古いフレームで判定する → #26 と同じく、0.25 秒より古いフレームは使わない
51. `[E2E]` 2台とも強く押している → 押す力が 50 以上になったのが最も新しい方をクリック元にする
52. `[E2E]` Force Touch のトラックパッドと、押す力が分からないトラックパッドが混在している → Force Touch の方が押されていなければ、押す力が分からない方で従来どおり判定する。ただし Force Touch の方にも触れているなら、どちらのクリックか分からないのでそのまま通す（main と同じ。61）
53. `[E2E]` 3本指クリックでは強く押すのが1本だけ（実機で確認）なのに、全部の指の押す力を見て押されていないと判断する → 指ごとの最大値を使う（BTT と同じ）
54. `[E2E]` フィクスチャや記録に押す力が無いとき、押す力 0 とみなして全部のクリックを素通りさせてしまう → 押す力が無いフレームは「押す力が分からないトラックパッド」として扱う
55. 押す力が分からないトラックパッド（Force Touch 非対応）で、押す力のフィールドに意味の無い値が入っていて誤判定する → `MTDeviceSupportsForce` が真のトラックパッドだけ押す力を読む
56. （既知の制限）トラックパッドを強く押し始めてから（クリックせずに）0.2 秒以内にマウスでクリックすると、トラックパッドのクリックとみなされる
57. `[E2E]` トラックパッドを強く押し続けている間（クリックはしない）、「最近押された」が更新され続け、何秒あとのマウスのクリックも変換してしまう（PR #6 の Codex レビューで指摘）→ 押し始め（押す力が 50 を下回った状態から超えた時点）から 0.2 秒を過ぎたらクリック元とみなさない
58. `[E2E]` 57 の対処で、ゆっくり押し込んだクリック（50 を超えてからクリックが確定するまで 80ms 以上かかる）を見逃す → 押し始めからの期限は 0.2 秒と長めにとる
59. `[E2E]` 押す力がいったん 50 を下回ってから（指は置いたまま）もう一度押したとき、最初の押し始めの時刻のままで判定し、2回目のクリックを見逃す → 50 を下回ったら押し始めを測り直す
60. `[E2E]` 押す力を待っている間に TipTap左の判定が進み、左クリックと中クリックが二重に出る（PR #6 の Codex レビューで指摘）→ 左クリックが届いた時点で TipTap に伝えてから待つ
61. `[E2E]` Force Touch の方の接触を数から外して「押す力が分からない方が1台だけ」と判定し、Force Touch に指を置いたまま非対応の方に4本置いてマウスでクリックすると ⇧⌘5 になる（PR #6 の Codex レビューで指摘）→ 押す力が分からない方で判定するのは、ほかのトラックパッドに新しい接触が無いときだけ

## TipTap左

10. `[E2E]` 基本形（2本固定 → 左をタップ）で発火しない
11. `[E2E]` 右側をタップしたのに発火する（TipTap右は対象外）
12. `[E2E]` タップが長すぎる（押し続け）のに発火する。BTT は「候補になってから 0.25 秒未満で離す」で測る
13. `[E2E]` タップした指の移動量で弾いてしまう。BTT はタップした指の移動を見ていない（以前の実装は 0.04 以上動いたら無視していた）
14. `[E2E]` 固定側の2本が動いている（2本指スクロール中）のに発火する。BTT と同じく、候補になった時点と離した時点で固定側の左端の x が 0.1 を超えてずれたら発火しない
15. `[E2E]` タップ中に物理クリックが起きた（3本指クリック）のに TipTap も発火して二重になる
16. `[E2E]` 固定側が1本 / 3本のときに発火する（2本固定のみ対象）
17. `[E2E]` 固定側の指が先に離れた場合に発火する
18. `[E2E]` 3本同時に置いただけ（固定が先に存在しない）で発火する
19. `[E2E]` 1回のタップで2回以上発火する
20. フレームのタイムスタンプが巻き戻る・欠落する
32. `[E2E]` 2本を置いた直後に3本目を置くと、そのまま残していても発火しない（実機で報告）。BTT は「2本になってから 0.2 秒経った時点で3本目がまだ置かれていれば候補にする」ので、3本目を早く置いてもよい
33. `[E2E]` 3本の指の x の広がりが 0.6 以上（離れすぎ）なのに発火する（BTT の条件）
34. `[E2E]` タップした指と固定側の左端の差が 0.03 未満（ほぼ同じ位置）なのに発火する（BTT の BTTTwoFingerTipTapMinSpread の既定値）
35. `[E2E]` 発火の直後（0.2 秒以内）に次のタップをしても発火してしまう。BTT は発火のあと、2本指のまま「準備」を測り直す
36. `[E2E]` 3本目を置いてから候補になるまでの間に物理クリック（3本指クリック）すると、中クリックが二重に出る（PR #4 のレビューで指摘）。BTT と同じく、クリックから 0.7 秒以内は候補にしない

## 環境・権限

21. アクセシビリティ権限が無く、イベントタップが作れないまま黙って動かない → 起動時に明示的に失敗させる
22. イベントタップがタイムアウトで OS に無効化され、以後効かなくなる → 再有効化する
23. MultitouchSupport が読み込めない / トラックパッドが無い → 明示的に失敗させる
24. `[E2E]` トラックパッドが複数（内蔵 + Magic Trackpad）あるとき、指の本数が混ざる → デバイスごとに管理し、押す力でクリック元を決める（分からなければ新しい接触が1台だけのときだけ判定する）
25. BetterTouchTool と併用すると二重に発火する → README で BTT の該当トリガーを無効化するよう案内
37. 起動中にアクセシビリティ権限を外すと、残ったイベントタップが左クリックを止め、トラックパッドもマウスもクリックできなくなる（実機で報告、#3）→ 権限を1秒ごとに確認し、外れたらタップを取り外す
38. 権限が無い状態で OS にタップを無効化され、そのたびに再有効化してしまう（22 の対処が裏目に出る）→ 再有効化の前に権限を確認し、無ければタップを取り外す
39. 権限が外れたのに、メニューバーは動作中のまま見える → アイコンを無効表示にし、メニューに「権限がありません」と出す
40. 権限が無いあいだも TipTap左を判定し、ハプティックだけ鳴って中クリックは出ない（イベントの送信には権限が要る）→ 権限が無いあいだは動作もハプティックも出さない
41. 権限を戻しても再開せず、アプリの再起動が必要になる → 権限が戻ったらタップを作り直す（作れなければ次の確認で再試行する）
42. 3本指クリックの押下中に権限が外れると、中ボタンの解放が送られず押しっぱなしになる（権限が無いので解放を送る手段も無い）→ 既知の制限。次に中クリックすれば戻る。押下中の判定は捨てて、再開後の解放を誤って変換しない
