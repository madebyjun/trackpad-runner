# 想定される失敗パターン

実装前に書き出した「壊れ方」の一覧。E2E（リプレイ）フィクスチャはこの一覧を元に作っている。
`[E2E]` が付いたものは `e2e/fixtures/` にケースがある。

## 対象機能

| トリガー | 動作 |
|---|---|
| 3本指でクリック | 中クリック（カーソル位置） |
| 4本指でクリック | ⇧⌘5 |
| TipTap左（2本指を置いたまま、その左側を1本指でタップ） | 中クリック（カーソル位置） |

## クリック系（3本指 / 4本指）

1. `[E2E]` 1本指・2本指の普通のクリックを誤って変換してしまう（通常操作が壊れる。最悪の失敗）
2. `[E2E]` 3本指クリックが中クリックにならない
3. `[E2E]` 4本指クリックで ⇧⌘5 が出ない、または左クリックも同時に通ってしまう
4. `[E2E]` 押下中に指の本数が変わる（3本で押して2本で離す等）→ down と up の種類が食い違い、ボタンが押しっぱなしになる。down 時の判定を up まで保持する必要がある
5. `[E2E]` 3本指で押したままドラッグ → leftMouseDragged が素通りして、中ボタン押下中に左ドラッグが混ざる
6. `[E2E]` 5本以上の指 → 何もしない（素通り）べきところで誤発火
7. `[E2E]` 触れていない指（ホバー・離れかけの状態）まで本数に数えてしまう
8. ⇧⌘5 送信時に修飾キーが残って、その後の入力に Shift/Cmd が付く
9. `[E2E]` ハプティックや ⇧⌘5 が押した瞬間に出てしまう（BTT は押したときは通常のクリック感だけで、離したときに設定したハプティックと動作が出る）
26. `[E2E]` タッチデータが古い（デバイスのコールバックが止まっている）まま判定してしまう → 4本触れた最後のフレームのあとの通常クリックが ⇧⌘5 になる（PR #1 のレビューで指摘）。0.25 秒より古いフレームは使わない
27. `[E2E]` 左クリックの入力元を見ずに判定してしまう → 片方のトラックパッドに4本置いたまま、別のトラックパッドを1本指でクリックすると ⇧⌘5 になる（PR #1 のレビューで指摘）。CGEvent にはクリック元のトラックパッドの情報が無いので、新しい接触が複数のトラックパッドにあるときは判定せずそのまま通す
28. （既知の制限）トラックパッドに3本以上置いたまま、マウスでクリックすると変換されてしまう。クリック元の特定は別イシューで対応する

## TipTap左

10. `[E2E]` 基本形（2本固定 → 左をタップ）で発火しない
11. `[E2E]` 右側をタップしたのに発火する（TipTap右は対象外）
12. `[E2E]` タップが長すぎる（押し続け）のに発火する。BTT は「候補になってから 0.25 秒未満で離す」で測る
13. `[E2E]` タップした指の移動量で弾いてしまう。BTT はタップした指の移動を見ていない（以前の実装は 0.04 以上動いたら無視していた）
14. `[E2E]` 固定側の2本が動いている（2本指スクロール中）のに発火する。BTT と同じく、候補になった時点と離した時点で固定側の左端の x が 0.1 を超えてずれたら発火しない
15. `[E2E]` タップ中に物理クリックが起きた（3本指クリック）のに TipTap も発火して二重になる
16. `[E2E]` 固定側が1本 / 3本のときに発火する（2本固定のみ対象）
17. `[E2E]` 固定側の指が先に離れた場合に発火する
18. `[E2E]` 3本同時に置いただけ（固定が先に存在しない）で発火する
19. `[E2E]` 1回のタップで2回以上発火する
20. フレームのタイムスタンプが巻き戻る・欠落する
32. `[E2E]` 2本を置いた直後に3本目を置くと、そのまま残していても発火しない（実機で報告）。BTT は「2本になってから 0.2 秒経った時点で3本目がまだ置かれていれば候補にする」ので、3本目を早く置いてもよい
33. `[E2E]` 3本の指の x の広がりが 0.6 以上（離れすぎ）なのに発火する（BTT の条件）
34. `[E2E]` タップした指と固定側の左端の差が 0.03 未満（ほぼ同じ位置）なのに発火する（BTT の BTTTwoFingerTipTapMinSpread の既定値）
35. `[E2E]` 発火の直後（0.2 秒以内）に次のタップをしても発火してしまう。BTT は発火のあと、2本指のまま「準備」を測り直す
36. `[E2E]` 3本目を置いてから候補になるまでの間に物理クリック（3本指クリック）すると、中クリックが二重に出る（PR #4 のレビューで指摘）。BTT と同じく、クリックから 0.7 秒以内は候補にしない

## 環境・権限

21. アクセシビリティ権限が無く、イベントタップが作れないまま黙って動かない → 起動時に明示的に失敗させる
22. イベントタップがタイムアウトで OS に無効化され、以後効かなくなる → 再有効化する
23. MultitouchSupport が読み込めない / トラックパッドが無い → 明示的に失敗させる
24. `[E2E]` トラックパッドが複数（内蔵 + Magic Trackpad）あるとき、指の本数が混ざる → デバイスごとに管理し、新しい接触が1台だけのときだけ判定する
25. BetterTouchTool と併用すると二重に発火する → README で BTT の該当トリガーを無効化するよう案内
37. 起動中にアクセシビリティ権限を外すと、残ったイベントタップが左クリックを止め、トラックパッドもマウスもクリックできなくなる（実機で報告、#3）→ 権限を1秒ごとに確認し、外れたらタップを取り外す
38. 権限が無い状態で OS にタップを無効化され、そのたびに再有効化してしまう（22 の対処が裏目に出る）→ 再有効化の前に権限を確認し、無ければタップを取り外す
39. 権限が外れたのに、メニューバーは動作中のまま見える → アイコンを無効表示にし、メニューに「権限がありません」と出す
40. 権限が無いあいだも TipTap左を判定し、ハプティックだけ鳴って中クリックは出ない（イベントの送信には権限が要る）→ 権限が無いあいだは動作もハプティックも出さない
41. 権限を戻しても再開せず、アプリの再起動が必要になる → 権限が戻ったらタップを作り直す（作れなければ次の確認で再試行する）
42. 3本指クリックの押下中に権限が外れると、中ボタンの解放が送られず押しっぱなしになる（権限が無いので解放を送る手段も無い）→ 既知の制限。次に中クリックすれば戻る。押下中の判定は捨てて、再開後の解放を誤って変換しない
